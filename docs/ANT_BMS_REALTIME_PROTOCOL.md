# ANT BMS 实时监测协议参考

> 适用对象：ESP32 + 显示屏、Web Bluetooth、上位机和负责实现这些客户端的 agent。
>
> 范围：仅 ANT BMS 实时监测帧（功能码 `0x11`）。本文不授权、也不描述参数写入、MOS 控制、校准、认证、OTA 或其他控制类操作。

## 快速实现清单

1. 通过 BLE 串口服务连接设备；常见服务/特征组合为 `FFE0/FFE1`，也可能是 `FFF0` 服务下的 `FFF3 → FFF4` 或 `FFF5 → FFF6`。
2. 订阅通知特征，向写特征发送只读状态查询帧。
3. 按 `7E A1` 找帧头，使用第 6 个字节（索引 `5`）作为 payload 长度，完整帧长度为 `payloadLength + 10`。
4. 校验帧尾与 CRC-16/Modbus；失败帧直接丢弃，不要用损坏数据刷新 UI。
5. 按电芯串数 `C` 与温度数量 `T` 计算动态偏移；任何字段读取前都必须确认数据长度足够。

## 只读状态查询

请求帧（十六进制）：

```text
7E A1 01 00 00 BE 18 55 AA 55
```

这是当前项目唯一发送的业务指令。状态响应的功能码为 `0x11`。

## 帧格式

```text
7E A1 | 功能码 | 地址低 | 地址高 | Payload 长度 | Payload... | CRC 低 | CRC 高 | AA 55
```

| 字段 | 偏移 | 长度 | 说明 |
| --- | ---: | ---: | --- |
| 帧头 | 0 | 2 | 固定为 `7E A1` |
| 功能码 | 2 | 1 | 实时状态响应为 `0x11` |
| 地址 | 3 | 2 | 小端序 |
| Payload 长度 | 5 | 1 | 后续 payload 的字节长度 |
| Payload | 6 | N | 实时状态数据 |
| CRC | `6 + N` | 2 | CRC-16/Modbus，小端序（低字节在前） |
| 帧尾 | `8 + N` | 2 | 固定为 `AA 55` |

### CRC-16/Modbus

- 初始值：`0xFFFF`
- 多项式（右移形式）：`0xA001`
- 输入范围：从索引 `1` 的 `A1` 开始，至 payload 最后一个字节结束；不包含帧头 `7E`、CRC 与帧尾。
- 结果写入/读取均为小端序。

## Payload 字节序与动态偏移

多字节数值均为小端序。令：

```text
C = payload[3]  // 电芯串数
T = payload[2]  // 温度传感器数量
D = 2 * C + 2 * T
```

Payload 的前 28 个字节固定，随后依次是 `C` 个单体电压（各 2 字节）和 `T` 个温度（各 2 字节）。因此后续字段必须根据 `D` 计算，不能硬编码总偏移。

| 字段 | Payload 偏移 | 类型 / 缩放 | 单位 |
| --- | --- | --- | --- |
| 权限 | `0` | `u8` | — |
| 电池状态 | `1` | `u8` | 枚举 |
| 温度数量 | `2` | `u8` | 个 |
| 电芯串数 | `3` | `u8` | 串 |
| 保护位 | `4` | 64 bit | 位图 |
| 告警位 | `12` | 64 bit | 位图 |
| 均衡/推送位 | `20` | 64 bit | 位图 |
| 单体电压 | `28 + 2*i` | `u16 / 1000` | V |
| 温度 | `28 + 2*C + 2*i` | `i16` | °C |
| MOS 温度 | `28 + D` | `i16` | °C |
| 均衡温度 | `30 + D` | `i16` | °C |
| 总电压 | `32 + D` | `u16 / 100` | V |
| 实时电流 | `34 + D` | `i16 / 10` | A |
| SOC | `36 + D` | `u16` | % |
| SOH | `38 + D` | `u16` | % |
| 放电 MOS | `40 + D` | `u8` | 枚举 |
| 充电 MOS | `41 + D` | `u8` | 枚举 |
| 均衡状态 | `42 + D` | `u8` | 原始值 |
| BMS 类型 | `43 + D` | `u8` | 原始值 |
| 物理总容量 | `44 + D` | `u32 / 1,000,000` | Ah |
| 剩余容量 | `48 + D` | `u32 / 1,000,000` | Ah |
| 累计循环容量 | `52 + D` | `u32 / 1000` | Ah |
| 实时功率 | `56 + D` | `i32` | W |
| 运行时间 | `60 + D` | `u32` | s |
| 均衡单体位 | `64 + D` | 32 bit | 位图 |

## 充电扩展字段

扩展部分不是每台设备都会上报。必须逐字段判定：只有 `payload.length >= 字段偏移 + 字段长度` 时才能解析；未上报即“不可用”，不要填充为 `0` 或推测数值。

| 字段 | Payload 偏移 | 类型 / 缩放 | 单位 |
| --- | --- | --- | --- |
| 充电剩余时间 | `114 + D` | `u16` | 分钟 |
| 放电剩余时间 | `116 + D` | `u16` | 分钟 |
| 充电器输出电压 | `124 + D` | `u16 / 10` | V |
| 充电器输出电流 | `126 + D` | `u16 / 10` | A |
| 充电器状态字 | `128 + D` | `u16` | 位字段 |

充电器状态字的解释：

```text
bit 15      -> chargerOnline（1 = 在线）
bits 0..14  -> chargerState（保留原始数值，尚无可靠枚举）
```

剩余时间仅适合在充电/放电状态对应时显示。`0xFFFF` 或未上报的值应显示为“暂不可用”。分钟可格式化为 `X 小时 Y 分钟`。

## 状态、方向与显示建议

| 电池状态码 | 建议文案 |
| ---: | --- |
| 0 | 未知 |
| 1 | 静置 |
| 2 | 充电 |
| 3 | 待机 |
| 4 | 放电 |
| 5 | 故障 |

- 电流必须按 `i16` 解析，保留正负号。
- 当前公开实现未验证“电流正/负号”本身等价于充电或放电；方向标签应优先依据电池状态码 `2` / `4`。
- MOS 状态常用值：`0 = 关闭`、`1 = 开启`；其余值应保留为原始状态值。

## 轮询建议

- 连接后的首次状态读取：约 `1 秒` 内执行一次。
- 设备处于充电或放电状态：约 `800 ms` 一次，以提高电流、功率和剩余时间的可见更新速度。
- 静置、待机或未知状态：约 `2 秒` 一次，减少 BLE 通信负担。
- 任意时刻均应避免并发发送多个未完成的读取请求；断开连接后必须停止定时器与通知订阅。

## ESP32 实现要点

1. 使用通知回调累积字节流，BLE 通知可能把一帧拆成多段，也可能把多帧拼在一起。
2. 帧解析器应持续寻找 `7E A1`，计算完整长度后再取帧；无效帧只丢弃当前帧并继续同步。
3. 使用有符号解析函数读取 `i16` / `i32`，不要先转无符号再缩放。
4. 将“协议原始值”和“UI 格式化文本”分层：解析层保留数值，显示层才处理单位、时间和不可用提示。
5. 显示屏优先展示：SOC、总电压、实时电流、运行状态、容量、充放电 MOS、温度、告警数量；扩展充电器数据存在时再显示。
